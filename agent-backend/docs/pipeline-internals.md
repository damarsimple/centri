# Pipeline Internals — Agent Behavior Reference

> Precise description of what the `agent-backend` orchestrator actually does, step
> by step, so changes to agent behavior can be made safely. Source of truth:
> `prompts/orchestrator.txt` (~990 lines), the frozen pipeline in
> [`workspace_lib/analysis/`](../workspace_lib/analysis/README.md), the three
> subagents in `.pi/agent/agents/`, and `worker/tasks.py`. Companion docs:
> [agents-behaviour.md](agents-behaviour.md), [data-contract.md](data-contract.md),
> [subagents.md](subagents.md), [architecture-overview.md](architecture-overview.md).

## 1. What it is

`agent-backend` is an **agentic** circular-motion video-analysis pipeline. It does
**measurement + static reporting only** — there is no interactive/adaptive
pedagogy here (see [architecture-overview.md](architecture-overview.md) for how it
relates to the inquiry tutor in `fastapi-gpt`).

The worker (`worker/tasks.py`) runs the analysis by shelling out to the **`pi`
agent CLI**:

```
pi -p <orchestrator.txt> --mode json --model llama.cpp-lab2/Qwen3.6-35B-A3B-UD-Q4_K_XL.gguf
```

The agent reads the orchestrator prompt as instructions, **writes and executes its
own Python step scripts** inside the per-job workspace, calls the remote tracking
API exactly once, spawns three subagents, compiles two LaTeX PDFs, then exits. A
second `pi` run (`--mode text`, the extractor) reports which output files exist.

Key consequence: **the perception step scripts (Steps 1–5) are generated by the LLM
at run time** from the prompt. The prompt is the specification; the agent fills in
anything the prompt leaves implicit.

**The kinematics is no longer agent-authored.** Steps 5–8 of the old design
(trajectory cleaning, calibration, active detection, kinematics, phases, and the
`stats.json` write) now live in a **frozen, seeded package**,
[`workspace_lib/analysis/`](../workspace_lib/analysis/README.md), copied into every
workspace by `app/workspace.py::seed_pipeline`. The agent's perception steps write a
single handoff file, `pipeline_inputs.json`, and Step 6 runs `python -m analysis.run`.
This was introduced because agent-authored kinematics produced 28 distinct
`stats.json` schemas across 30 jobs, bare `NaN` in 17, and `center_drift_px` ranging
8.9→1013 px on the *same* video. The frozen pipeline makes "same `pipeline_inputs.json`
→ byte-identical `stats.json`" hold by construction (verified by `tools/gt_harness.py`).

## 2. Hard rules the agent must obey

From `orchestrator.txt` "HARD RULES":

- **Tracking is remote-only.** Never run SAM2/SAM3/segment-anything locally. The
  only tracking interface is `POST {TRACKING_API_URL}/track` via `requests`.
- **Exactly ONE tracking API call** for the whole pipeline, made in Step 2 on the
  original video, cached to `analysis_output/data/api_cache.json`. If the cache
  exists, the API is not called at all. Crop-space trajectories are derived by
  subtracting the crop offset — never by a second API call.
- **All downstream pixel coordinates are in cropped-video space**, with one exception:
  the `pipeline_inputs.json` contract carries the trajectory + center in raw full-frame
  (`"display"`) space and the frozen `contract.py` subtracts the crop offset once, for
  both together (the display→cropped transform was moved off the agent in 2026-06 — see
  [data-contract.md](data-contract.md) §3.1a). The crop offset also lives in `stats.json`
  / `roi_crop_meta.json` for external reference.
- Work only inside the workspace dir. Never fabricate measurements — every number
  comes from code. Missing detections → `NaN` (never repeat last-known). Idle
  intervals are excluded from summary statistics.
- ffprobe is the sole source of truth for FPS and aspect ratios.
- Step order is strict: 1 → 2 → 3 → 4 → 5 → 6. No monolithic script.
- **Kinematics is frozen.** The agent must never reimplement, edit, or "improve"
  anything under `analysis/`. Its job ends at writing `pipeline_inputs.json`.

## 3. Inputs

| Variable | Source | Meaning |
|---|---|---|
| `VIDEO_PATH` | env (`input_video.mp4`) | the uploaded video, dropped into the workspace |
| `TRACKING_API_URL` | env (default `http://192.168.1.13:8086`) | SAM-based tracking server |
| `SIDECAR_JSON` | `sidecar.json` in workspace | scene geometry (below) |

**Sidecar schema** (produced by the app, parsed in Step 1):

```jsonc
{
  "tracked_object":   { "visual_cues": ["red ball"] },   // label(s) of the moving object
  "reference_geometry": {
    "label":          "lazy susan",                       // calibration object
    "physical_size":  0.30                                // real size in metres (optional)
  },
  "rotation_center_frac": [0.52, 0.43]                    // user-marked spin axis (authoritative)
}
```

> `reference_geometry.bbox_center_px` was removed (2026-06) — dead/redundant; the axis
> comes from `rotation_center_frac`, the reference centre from tracking.

If `physical_size` is omitted, Step 5 estimates it from world knowledge and raises
the `physical_size_estimated` flag.

## 4. The six sequential steps

Steps 1–5 are **agentic perception** (LLM-authored Python); Step 6 runs the
**frozen pipeline**. All log to `analysis_output/debug/pipeline.log`.

| Step | Name | Authored by | Does | Writes |
|---|---|---|---|---|
| 1 | Scene Parsing & Metadata | agent | ffprobe (fps, res, SAR/DAR, rotation); parse sidecar; extract 1 fps preview frames + contact sheet | `frames_1fps/`, `debug/contact_sheet.jpg` |
| 2 | ROI Detection & Crop | agent | **the single tracking API call** (or cache hit); compute orbit-aware crop box; validate crop; crop with ffmpeg; transform trajectories to crop space | `roi/cropped.mp4`, `data/api_cache.json`, `data/roi_crop_meta.json` |
| 3 | Coordinate Validation | agent | extract one cropped frame; draw bbox+center per label; sanity-check centers in-bounds (visual only) | `debug/coord_validation_<label>.jpg` |
| 4 | Pre-Calibration Bootstrap | agent | rotation center = user mark (authoritative) or **median of reference detections** (`cx_calibration, cy_calibration`); aborts if <5 reference detections | calibration_log |
| 5 | Reference Sizing & Input Contract | agent | `diameter_px` = median bbox W/H of reference; resolve `physical_size_m` (sidecar or world-knowledge); assemble per-frame tracked centroid + center in **raw full-frame space** → **write `pipeline_inputs.json`** (`coordinate_space:"display"`; frozen `contract.py` does the display→cropped subtraction) | `data/pipeline_inputs.json` |
| 6 | Run Frozen Pipeline | **`analysis/`** | `python -m analysis.run`: RANSAC clean → calibration → active detection → kinematics → period → phases → locked `stats.json` | **`data/kinematics.csv`**, `data/stats.json`, `data/active_mask.npy` |

### Step 6 detail (the physics — now in `analysis/kinematics.py` & `geometry.py`)

Identical math to the old steps 5–8, lifted from a known-good run and made
deterministic. See [`analysis/README.md`](../workspace_lib/analysis/README.md).

- **Cleaning (`geometry.py`):** RANSAC circle fit drawing from a **seeded** RNG
  (`common.RANDOM_SEED`) → identical fit every run; radius-based outlier rejection
  (>2.5σ or >15 px → NaN); center kept at the mark unless absent and the fit is
  confident (`center_drift_px` flagged, never silently trusted).
- **Calibration:** `px_per_m = diameter_px / physical_size_m`; `r_fit_m = r_fit_px / px_per_m`.
- **Kinematics (`kinematics.py`):** θ unwrapped per segment; `r`,`θ` Savitzky-Golay
  smoothed (window ≈ fps/6); **ω computed once** (gradient + median filter) and reused
  for active detection, summary, period, *and* phases (the old two-ω inconsistency is
  gone); `v=|ω|·r_fit_m`; `aᶜ=ω²·r_fit_m` with ω-spike rejection.
- **Active mask:** |ω| above 10% (20% for <10 s clips) of ω_max, bursts ≥ min duration.
- **Period:** `T_primary = 2π/median(|ω_active|)`; FFT cross-check when the longest
  active run ≥ 3·T_primary, else `fft_skipped_insufficient_data`.
- **Phases:** dω/dt thresholds sustained ≥0.5 s → `INCREASE/DECREASE/STABLE`;
  `stable_mean_omega` = length-weighted θ(t) regression over STABLE segments.
- **Output:** `writer.py` writes the locked schema with `allow_nan=False` (missing
  values → JSON `null`) plus a sanity gate (low coverage, high drift, invalid period
  → validation flags).

## 5. Coordinate spaces (easy to get wrong)

- The tracking API returns coordinates in **display space** (post auto-rotation).
  Step 2 swaps width/height when metadata rotation is ±90/270.
- After the crop, **everything is in cropped-video space**. Nothing is remapped back.
  Subagents are told this explicitly; the only escape hatch is the offset in
  `roi_crop_meta.json` / the `roi_crop` block of `stats.json`.

## 6. Parallel + gated phases (summary)

Once `stats.json` exists, three subagents run in parallel via the `pi` `subagent`
tool (full detail in [subagents.md](subagents.md)):

- **A — Video Annotation** → `video_annotation/annotated_video.mp4` (does not block LaTeX).
  **Symbol-only**: overlays `r`/`v`/`ac`/`w` + a definitions legend, never numeric values
  (students measure, not read answers). Vetted reference seeded at
  `workspace_lib/analysis/render/annotate.py`.
- **B — Figure Generation** → 9 plots in `plots/` (**LaTeX waits on this**)
- **C — Question Generation** → `data/questions.json` (**LaTeX waits on this**)

All three remain LLM subagents; their definitions were hardened (no copy-able example
numbers, correct file paths) — see [subagents.md](subagents.md).

LaTeX compilation (gated on B + C) uses `latex-skill/scripts/compile_latex.sh` to
build `student_edition.pdf` and `teacher_key.pdf`. Finally the agent writes
`report.md`.

## 8. Sequential-phase outputs (the measurement results)

| File | Content |
|---|---|
| `data/pipeline_inputs.json` | **the perception→math handoff contract** (agent writes, `analysis/` reads) |
| `data/kinematics.csv` | **per-frame series** — `time_s, r_px, r_m, theta_rad, omega_rad_s, v_m_s, ac_m_s2, active` |
| `data/stats.json` | locked-schema summary kinematics + calibration + flags (consumed by subagents, returned by `/result`) |
| `data/active_mask.npy` | boolean per-frame active flag |
| `data/api_cache.json` | cached tracking response (prevents re-calls) |
| `data/roi_crop_meta.json` | crop offset + validation metadata |

> Note: `phases.json` is no longer written separately — phase labels and stable
> segments are embedded under `stats.json["phases"]`.

`kinematics.csv` is the canonical time-series and the key asset for both the
modality-substitution seam and the accuracy pilot — see
[data-contract.md](data-contract.md).
